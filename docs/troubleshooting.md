# Kaggle: UnidentifiedImageError после установки

В первой CPU-сессии пользователь подтвердил Python 3.13.18 и такой вывод:

```text
PIL loaded: 13.0.0
Image loaded: 13.0.0
Pillow installed: 12.3.0
Pillow core: 13.0.0
```

Причина — прежнее ограничение проекта `Pillow>=11.1,<13`. Установка понизила
Pillow на диске до 12.3.0, но notebook kernel продолжил использовать уже
импортированные модули и бинарное ядро 13.0.0. При загрузке других image plugins
эти версии смешивались. В traceback строки исходника `Image.open` даже указывали
на код другой функции: файл на диске уже отличался от загруженного кода.

Это подтверждённое рассогласование окружения. Сам traceback не доказывает
повреждение FITVTO; отдельно прочитанный исходный `cloth[0]` оказался корректным
PNG 768×1024. Весь датасет на повреждения не проверялся.

## Что делать в текущей сессии

1. Обновить код и notebook до версии с исправлением. Локальные изменения нужно
   предварительно опубликовать в своём репозитории либо перенести в Kaggle как файлы.
2. Перезапустить notebook kernel/session в Kaggle, чтобы Pillow загрузился заново.
3. Выполнить notebook с первой ячейки. Установка и проверка версий идут до экспорта.
   Если pip изменил уже загруженную библиотеку, новая проверка явно сообщит о
   необходимости ещё одного перезапуска. Повторная установка при тех же версиях
   не вызывает бесконечных перезапусков.

Для устранения уже возникшего рассогласования достаточно перезапуска kernel;
исправленный pin предотвращает принудительное понижение Pillow 13 при следующей установке.
Текущее ограничение — `Pillow>=11.1,<14`.

Не стоит чинить это отдельными `importlib.reload(PIL...)`: они не гарантируют
согласованную перезагрузку plugin modules и бинарного ядра Pillow.

## Короткая диагностика без датасета

```python
import PIL
from PIL import Image
from importlib.metadata import version

print("PIL loaded:", PIL.__version__)
print("Image loaded:", Image.__version__)
print("Pillow installed:", version("Pillow"))
print("Pillow core:", Image.core.PILLOW_VERSION)
```

После перезапуска четыре версии должны совпадать. Состояние диска и загруженных
библиотек также сохраняется в `runtime.json`. Проверить его программно:

```python
from online_wearing.runtime import assert_runtime_matches_installed
assert_runtime_matches_installed()
```

Если при согласованных версиях действительно не декодируется отдельная запись,
экспорт теперь укажет ID примера, `source_index`, колонку, длину и первые 24 байта.
Запись не пропускается. Завершённые строки остаются в `manifest.jsonl.partial`.
По таким данным можно отличить пустое/неизвестное содержимое от корректного PNG/JPEG.

`FileNotFoundError` для `source.json` в диагностической ячейке означает, что
сохранённого subset сейчас нет по указанному пути. Для проверки Pillow он не нужен,
а `prepare_fitvto_subset()` создаёт его самостоятельно при новом экспорте.
